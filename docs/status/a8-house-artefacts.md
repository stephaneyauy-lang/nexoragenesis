# A8 house artefacts: what this repository does not hold

The A8 house build (`scripts/ntbuild_house.py`, fronted by `scripts/ntbuild_house.sh`) reconstructs the Nova producer from pinned sources through the house transport. Some of the things it needs are **not files of this repository**: they are published artefacts, produced elsewhere, checked by digest, and taken as parameters. This document says which ones, where each comes from, and how the build is told about them.

Nothing here is weakened by being external. The seed is still a **trust root**: its SHA-256 is the one the manifest pins, and the builder refuses (exit 78) when the artefact is absent or does not match. A missing artefact is a refusal, never a faked file.

## The short version

| Artefact | In this tree? | Where it comes from | How the build takes it |
|---|---|---|---|
| Seed PE (the P2 Nova compiler, 9 943 552 bytes) | **no** — published, and it must not be committed | the campaign archive, `house-stage-20261021-01/bootstrap/nova-native/nova-compiler.EFI` | `--seed-dir DIR` on the builder, `NG_SEED_DIR=DIR` in the shell front; default `<repo>/bootstrap/nova-native` |
| OVMF firmware (`CODE`) and the vars file (`VARS`) | **no** — the host's firmware, not the tree's | the host's OVMF/EDK2 installation | the transport's own `--code` / `--vars`; the house builder does not override them |
| House manifest (`bootstrap/nova-native/manifest.json`) | regenerated for this tree, read-only for the builder | `tools/validation/a8_manifest.py`, from the digests of the bytes on disk | read from the repository, never written by the builder |

## The seed PE: the pinned trust root

- **What it is.** The P2 Nova compiler as a PE32+ x86_64 image, 9 943 552 bytes, SHA-256 `6ab3b02dac3d5c833d1a19e3ef54fcd6fb804779a907f6dbf7e1bc4b9aba7891`. The house manifest pins it as `nova_compiler: {path: "nova-compiler.EFI", sha256: "6ab3b02d…"}`.
- **Where it comes from.** The campaign's read-only archive:
  `C:\NexoraGenesis\out\a8-selfhost-20261015\house-stage-20261021-01\bootstrap\nova-native\nova-compiler.EFI`
  (in WSL: `/mnt/c/NexoraGenesis/out/a8-selfhost-20261015/house-stage-20261021-01/bootstrap/nova-native/nova-compiler.EFI`).
- **Why it is not here.** It is a binary seed. The review of this pull request states it plainly: *"binary seeds and firmware are not supplied by this pull request"*. The transport already takes its images as arguments; the seed is the same kind of object.
- **How the build is told.** The seed is read from a **seed directory**:
  - `--seed-dir DIR` on `scripts/ntbuild_house.py` (before or after the command);
  - `NG_SEED_DIR=DIR` in the shell front, which forwards it as `--seed-dir`;
  - the builder itself also reads `NG_SEED_DIR` when `--seed-dir` is absent.
  The order is fixed: `--seed-dir`, then `NG_SEED_DIR`, then the repository path `bootstrap/nova-native`. **The default does not move.**
- **What the builder does with it, unchanged.** The directory says only *where* the bytes are read from:
  - `nova_compiler.path` is resolved **inside** the seed directory; a path that escapes it is refused (`path-escape`);
  - the SHA-256 of the bytes on disk must equal the digest the manifest pins, or the run is refused (`seed-digest-mismatch`);
  - the PE64 shape is checked (`not-pe64`);
  - a seed that is not there is refused (`seed-missing`), never replaced by another file;
  - the seed is re-read at the end of the build, and a seed that moved under the build is refused (`seed-changed-during-build`);
  - the directory actually used is written into `build.json` (`seed.directory`, `seed.resolved_path`).
  The seed stays a **trust root**: it is pinned and checked, and the build never claims to prove where it came from.

## The OVMF firmware and the vars file

The transport boots QEMU, and QEMU boots OVMF. Those two files are the host's firmware, not this repository's.

- The transport takes them as arguments: `--code` (firmware) and `--vars` (the writable variables file), with the defaults `/usr/share/OVMF/OVMF_CODE_4M.fd` and `/usr/share/OVMF/OVMF_VARS_4M.fd` — the host's `ovmf` package.
- The house builder calls the transport **without** `--code` and `--vars`, so the transport's defaults are what a house run uses; a run on a host without those files is refused by the transport's own preflight (`missing firmware: …`), not by the builder.
- The transport copies the vars file into the run directory (`vars.fd`) before booting, so the host's file is never written to.
- To use other firmware, call the transport with `--code` / `--vars`; that is the transport's interface, and the house builder does not extend it.

## The house manifest

- **Where it lives.** `bootstrap/nova-native/manifest.json`, schema `NEXORA_NOVA_BOOTSTRAP_V1`.
- **Who writes it.** Not the builder: the builder only ever *reads* the manifest. The manifest for this reorganized tree is regenerated by the A8 manifest generator, `tools/validation/a8_manifest.py`, which reads the stage's manifest for the lists and the roles, maps every path through `docs/architecture/source-map.csv`, and recomputes every digest from the bytes on disk. This document does not write it and does not describe its contents.
- **What the builder does with it.** It pins bytes and authorizes nothing: a boolean inside it opens nothing, an unknown key is reported and ignored, and `bootstrap_history` is descriptive, never a proof. A missing manifest is refused (`manifest-missing`); the builder has no fallback manifest and will not invent one.

## What this tree does hold

- **The two pinned S0 producers**: `compiler/runtime/runtime-v2-s0.ntasm` and `compiler/runtime/uefi-host-s0.ntasm` (both described in `compiler/runtime/README.md`). Their source digests, and the digests of the images the transport must rebuild from them, are pinned by the house manifest. The builder assembles both through the transport and checks the images it gets back against the manifest.
- **The Nova sources**: the `.nova` closure under `compiler/nova/`, nested by responsibility (`analysis`, `backend`, `drivers`, `formats`, `frontend`, `inspectors`, `ir`, `macros`), listed by the manifest and packed into the `NVSRC001` bundles the manifest pins.
- **The seed0 ledger**: `bootstrap/seed/seed0-bytes.md` is the byte-for-byte authority of the first seed form (layout, PE/COFF fields, the eight instructions, the canonical hex dump) and `bootstrap/seed/seed0.sha256` gives its reference digest, `69fa9aedbe1d009457c6cd065a78d90d1d997111d49719ce79fe3045603901d0`. The **ledger** is in the tree; the 1 536-byte image itself is not (it is in the campaign's tree, `bootstrap/seed/seed0.efi`). The ledger is not the house seed: the house seed is the 9.9 MB P2 Nova compiler described above.
- **The build and the transport**: `scripts/ntbuild_house.py`, `scripts/ntbuild_house.sh`, `scripts/nova_native_transport.py`.

## The exact commands

The seed lives outside the tree; point the build at it. From the repository root, in WSL (the house build runs on the Linux/WSL host; it needs `fcntl` for its CPU gate):

```bash
# 1. the shell front, with the environment variable
NG_SEED_DIR=/mnt/c/NexoraGenesis/out/a8-selfhost-20261015/house-stage-20261021-01/bootstrap/nova-native \
  bash scripts/ntbuild_house.sh build

# 2. the shell front, with the option (the flag belongs after the command)
bash scripts/ntbuild_house.sh build \
  --seed-dir /mnt/c/NexoraGenesis/out/a8-selfhost-20261015/house-stage-20261021-01/bootstrap/nova-native

# 3. the builder alone
python3 scripts/ntbuild_house.py \
  --seed-dir /mnt/c/NexoraGenesis/out/a8-selfhost-20261015/house-stage-20261021-01/bootstrap/nova-native \
  build

# 4. the self-host route, same seed
NG_SEED_DIR=/mnt/c/NexoraGenesis/out/a8-selfhost-20261015/house-stage-20261021-01/bootstrap/nova-native \
  bash scripts/ntbuild_house.sh selfhost

# 5. verify the pins where the seed really is, before spending an hour in QEMU
bash scripts/ntbuild_house.sh pins \
  --seed-dir /mnt/c/NexoraGenesis/out/a8-selfhost-20261015/house-stage-20261021-01/bootstrap/nova-native

# 6. the policy, which states the seed rule
bash scripts/ntbuild_house.sh policy
```

On Windows, the same directory is `C:\NexoraGenesis\out\a8-selfhost-20261015\house-stage-20261021-01\bootstrap\nova-native`; a native Windows run of the house builder is not supported (the CPU gate needs `fcntl`), so the paths above are the WSL ones.

Without `--seed-dir` and without `NG_SEED_DIR`, the builder looks in `<repo>/bootstrap/nova-native` and refuses with `class=seed-missing` (exit 78) when the seed is not there. That refusal is the correct answer for a checkout that does not ship the seed: the build asks for the artefact, it does not fake one.
